# UI Architect Flow UI 设计运行规格

本文件是 `agents/ui-architect.md` 的内部 UI 设计流程规格，不是 Claude Code agent 文件，不包含 agent frontmatter，不被主调度器直接调用。

## 1. 定位与边界

`ui-architect` 是 Superlooper 在 PRD 审核通过后、系统设计前的 UI 设计 subagent。它的价值是把已审核 PRD 转换为页面结构、信息架构、交互体验、内容策略、视觉系统和可预览 HTML 原型。

本文件只约束 `ui-architect` 的内部设计流程，不覆盖 `agents/ui-architect.md` 的 payload、输出路径、输出格式和禁止事项。当本文件与 `skills/superlooper/SKILL.md` 冲突时，以主调度协议为准。

职责边界：`agents/ui-architect.md` 是输出契约源，负责 payload、必读上下文、输出产物、质量扫描和禁止事项；本文件是内部设计流程源，负责 UI 设计顺序、规则维度、设计知识来源和细节决策标准。两者重复时，正式输出以 `agents/ui-architect.md` 为准。

## 2. 输入基线

`ui-architect` 必须以已审核 PRD 为唯一需求基线，不得回到原始需求重新做需求分析。用户自然语言反馈由主调度器先归一化；归一化为 UI 重设计反馈时，`ui-architect` 只按 `feedback_report` 重写 UI 设计产物，不生成 PRD、系统设计、模块拆分或执行清单。

必须从 PRD 中读取并消费以下章节：

| PRD 内容 | UI 设计阶段处理方式 |
| --- | --- |
| 需求定义总览 | 映射为 UI 目标、目标用户、关键场景和页面集合 |
| 功能性需求 | 转换为页面、区块、组件、交互、状态和任务流 |
| 非功能性需求 | 转换为性能感知、响应式、可访问性、可用性和反馈规则 |
| 约束与合规要求 | 转换为权限展示、脱敏展示、错误提示和禁止 UI 行为 |
| 范围边界 | `MUST_NOT` 不得进入页面、文案、交互、视觉或 preview HTML |
| 验收标准 | 转换为页面验收点、交互验收点和 preview 覆盖点 |
| 需求追溯矩阵 | 作为页面 ID、交互 ID、状态矩阵和验收映射的编号来源 |
| 决策记录 | 将 `DEC-*` 转换为 UI 约束、页面结构、视觉边界或内容策略 |
| 非阻塞开放问题 | 对建议处理阶段包含 UI、交互、前端、页面、视觉、内容或体验的 `OPEN-*` 采用 PRD 默认处理方式 |

## 3. 项目模式分支

UI 设计默认服务新项目。除非 payload 显式进入 brownfield 分支，否则不得扫描已有前端结构。

| 分支 | 触发条件 | 设计依据 | 禁止事项 |
| --- | --- | --- | --- |
| 新项目默认路径 | `project_mode` 缺失或 `project_mode=greenfield` | 已审核 PRD、用户参考材料、本文件规则、模型 UI/UX 能力 | 禁止读取已有前端结构、组件库、样式体系或路由习惯 |
| brownfield 可选路径 | `project_mode=brownfield` 且 `existing_frontend=true` | 已审核 PRD、本文件规则、用户参考材料、已有前端事实 | 禁止用已有前端事实覆盖 PRD；禁止修改目标项目业务文件 |
| brownfield 未授权 | `project_mode=brownfield` 且 `existing_frontend` 不是 `true` | 按新项目默认路径处理 | 禁止执行已有前端扫描 |
| 输入不一致 | `existing_frontend=true` 但 `project_mode` 不是 `brownfield` | 按新项目默认路径处理 | 禁止因为 `existing_frontend=true` 单独触发扫描 |

brownfield 扫描只允许识别兼容约束、复用组件、路由习惯和样式冲突。新项目默认路径下，UI 设计必须从零建立页面结构、交互方式、视觉系统和 preview HTML。

## 4. 内部设计流程

以下流程是内部推演顺序，不是新增主调度阶段，不改变 `skills/superlooper/SKILL.md` 的七流程主体调度语义。

```text
PRD 基线读取
-> 项目模式分支判断
-> UI 需求映射
-> 页面形态设计
-> 信息架构设计
-> 交互体验设计
-> 内容策略设计
-> 设计知识库对齐
-> 视觉系统设计
-> preview HTML 原型设计
-> UI handoff 整理
-> PRD 到 UI 上游自校对
-> UI 质量扫描
```

## 5. UI 状态机与审核闭环

UI 设计阶段状态只允许：`NOT_STARTED`、`IN_PROGRESS`、`READY_FOR_REVIEW`、`CHANGES_REQUESTED`、`APPROVED`、`BLOCKED`、`FAILED`。

状态流转固定为：

```text
NOT_STARTED
-> IN_PROGRESS
-> READY_FOR_REVIEW
-> APPROVED
```

审核未通过时固定闭环为：

```text
READY_FOR_REVIEW
-> CHANGES_REQUESTED
-> IN_PROGRESS
-> READY_FOR_REVIEW
```

`BLOCKED` 表示 PRD 或参考材料缺失导致无法继续；`FAILED` 表示 UI 产物机器校验失败。`BLOCKED` 与 `FAILED` 均不得进入系统设计。

UI 重设计必须读取 `feedback_report` 与 `ui_revision`，未受影响页面 ID、交互 ID、需求追溯编号保持稳定，受影响项必须说明变更原因。

机器校验项包括固定产物存在、`ui-spec.md` 首个 YAML 状态块、`project_mode`、`preview.html` 自包含与 `ui-handoff.md` architect 消费关键词。人工审核项包括 UI 方向、页面层级、交互体验、视觉规则、内容策略和 preview HTML 是否符合用户预期。

## 6. UI 需求映射

UI 需求映射用于回答“PRD 中哪些内容必须被用户看见、操作、理解和验证”。

必须产出以下映射：

| 映射项 | 规则 |
| --- | --- |
| 用户角色到入口 | 每个核心角色必须有入口、默认首页或默认任务起点 |
| P0 需求到页面 | 每个 P0 用户可见需求必须映射到至少一个页面 |
| P0 需求到状态 | 每个 P0 用户可见需求必须覆盖加载中、空状态、正常、错误、成功中的适用状态 |
| 验收标准到 UI 行为 | 每条 UI 相关 `AC-*` 必须映射到页面行为或交互反馈 |
| 决策记录到 UI 约束 | 每个 UI 相关 `DEC-*` 必须形成页面、交互、文案或视觉约束 |
| 禁止范围到 UI 禁止项 | `MUST_NOT` 必须形成明确的 UI 禁止展示、禁止交互或禁止文案 |

PRD 未覆盖但 UI 成立所需的细节必须标记为 `[UI假设]`。影响需求方向、合规边界或核心业务目标的缺口必须报告主会话。

## 6. 页面形态设计

页面形态设计用于回答“这个产品由哪些页面和布局承载”。

### 6.1 页面类型

按 PRD 场景选择页面类型：

| 页面类型 | 使用场景 |
| --- | --- |
| 列表页 | 管理对象集合、检索、筛选、批量操作 |
| 详情页 | 查看单个对象的完整信息、状态和历史 |
| 表单页 | 创建、编辑、提交、配置对象 |
| Dashboard | 汇总指标、待办、告警和趋势 |
| 设置页 | 偏好、权限、组织、系统配置 |
| 引导页 | 首次使用、空白工作区、迁移流程 |
| 全屏沉浸式 | 编辑器、画布、监控大屏、流程编排 |
| 弹窗 | 短流程确认、轻量编辑、危险动作确认 |
| 抽屉 | 保留上下文的详情查看、侧向编辑和补充配置 |

### 6.2 布局范式

按信息密度和任务路径选择布局：

| 布局范式 | 使用场景 |
| --- | --- |
| 单栏 | 内容阅读、简单表单、移动端优先 |
| 双栏 | 左侧导航加右侧内容、主从详情 |
| 三栏 | 导航、列表、详情同时存在的工作台 |
| 网格 | 卡片集合、模板库、资源库 |
| 卡片墙 | 多维入口、功能展示、营销式首页 |
| 时间线 | 审批、日志、状态流转、历史记录 |
| 自由画布 | 流程图、拓扑图、拖拽编排、白板类产品 |

### 6.3 核心组件

必须按页面列出核心组件和状态：

- 导航。
- 卡片。
- 表格。
- 表单。
- 图表。
- 编辑器。
- 搜索框。
- 筛选器。
- 标签。
- 弹窗。
- 抽屉。
- Toast。
- 空状态。
- 骨架屏。

### 6.4 响应式策略

必须定义桌面端、平板端、移动端的布局变化：

| 断点 | 规则 |
| --- | --- |
| 桌面端 | 展示完整导航、主要操作、批量操作和高密度信息 |
| 平板端 | 保留核心导航，压缩辅助栏和次要信息 |
| 移动端 | 优先任务路径，使用底部 Tab、抽屉或单列布局 |

## 7. 信息架构设计

信息架构设计用于回答“用户如何找到目标内容并理解产品结构”。

### 7.1 导航结构

必须确定以下内容：

| 导航项 | 输出要求 |
| --- | --- |
| 主导航 | 顶部、左侧、底部或混合结构 |
| 一级条目 | 每个一级条目对应的业务对象或任务集合 |
| 二级条目 | 有层级时列出子项和归属关系 |
| 辅助导航 | 用户菜单、设置、帮助、通知的位置 |
| 移动端导航 | 汉堡菜单、底部 Tab、抽屉或精简入口 |

### 7.2 信息层级

每个关键页面必须分三层描述：

| 层级 | 含义 |
| --- | --- |
| 第一层级 | 首屏必须看到的关键信息和核心操作 |
| 第二层级 | 滚动可见或次要区域中的辅助信息和次要操作 |
| 第三层级 | 需要展开、进入详情或进入设置才能看到的高级信息 |

### 7.3 页面层级

页面层级必须明确：

- 首页或默认工作台。
- 一级功能页。
- 二级详情页。
- 三级配置页。
- 临时层：弹窗、抽屉、Popover、Toast。
- 异常页：403、404、500、无权限、无数据。

### 7.4 页面跳转逻辑

每条核心用户旅程必须描述：

```text
<起点页面> -> <中间页面或浮层> -> <结果页面或状态>
```

每条旅程必须包含：

- 入口触发方式。
- 成功路径。
- 失败路径。
- 回退方式。
- 面包屑或导航高亮。
- 中断后恢复位置。

### 7.5 内容分类与标签

必须定义内容分类原则：

| 分类方式 | 使用场景 |
| --- | --- |
| 按功能 | 工具型产品、后台管理、系统设置 |
| 按对象 | CRM、资产管理、项目管理、内容管理 |
| 按时间 | 日志、活动流、审批记录、任务排期 |
| 混合分类 | 复杂业务系统，需要同时支持对象和流程 |

标签体系必须说明预定义标签、用户自定义标签或混合标签，并给出命名一致性规则。

### 7.6 搜索体验

当 PRD 涉及检索、内容集合或管理对象时，必须设计搜索体验：

| 搜索项 | 输出要求 |
| --- | --- |
| 搜索入口 | 全局搜索、页面内搜索或二者并存 |
| 搜索范围 | 全站、当前模块、当前列表或指定对象集合 |
| 搜索建议 | 自动补全、热门搜索、历史搜索、快捷命令 |
| 筛选联动 | 关键词、标签、时间、状态、所有者和排序的关系 |
| 无结果处理 | 清晰说明、替代建议、清除筛选或创建入口 |
| 键盘体验 | `Cmd+K`、方向键选择、`Enter` 确认、`Esc` 退出 |

## 8. 交互体验设计

交互体验设计用于回答“用户操作界面时，每个瞬间得到什么反馈”。

### 8.1 交互设计哲学

必须定义：

- 核心原则。
- 动效性格。
- 反馈密度。
- 操作容错。
- 中断恢复方式。

### 8.2 核心组件微交互

| 组件 | 必须覆盖的状态 |
| --- | --- |
| 按钮 | 默认、悬停、按下、加载、禁用、成功 |
| 输入框 | 默认、聚焦、输入中、校验成功、校验失败、禁用 |
| 开关 | 默认、切换中、已开启、已关闭、禁用 |
| 列表 | 加载、悬停、选中、批量选择、空状态、删除 |
| 卡片 | 默认、悬停、点击、选中、拖拽、禁用 |
| 表格 | 排序、筛选、固定表头、行选择、批量操作、空结果 |
| 弹窗 | 出现、消失、遮罩、焦点锁定、确认、取消 |
| 抽屉 | 进入、退出、保留上下文、保存、放弃修改 |
| Toast | 成功、错误、警告、信息、可撤销操作 |

### 8.3 页面状态矩阵

每个关键页面必须包含状态矩阵：

| 状态 | 表现 | 用户动作 |
| --- | --- | --- |
| 加载中 | 骨架屏、渐进式加载或局部 loading | 等待、取消或浏览已加载区域 |
| 空状态 | 插画、说明文案和引导 CTA | 创建、导入、清除筛选或返回 |
| 正常 | 完整内容和主要操作 | 完成核心任务 |
| 错误 | 错误说明、原因和恢复动作 | 重试、返回、联系管理员或保存草稿 |
| 成功 | 成功反馈、结果摘要和下一步 | 继续操作、查看详情或返回列表 |

### 8.4 手势与快捷键

按平台定义：

| 平台 | 规则 |
| --- | --- |
| 移动端 | 下拉刷新、左滑删除、长按菜单、底部安全区 |
| 桌面端 | `Cmd+K` 搜索、`Cmd+S` 保存、`Esc` 取消、`Tab` 焦点移动 |
| Web 通用 | 链接可复制、返回可恢复、表单离开前提示未保存 |

### 8.5 可访问性

必须覆盖：

- 焦点顺序与视觉焦点态。
- 键盘可操作性。
- ARIA 标签。
- 文本与背景对比度不低于 4.5:1。
- 错误提示与字段绑定。
- 非颜色唯一表达。
- 弹窗焦点锁定与关闭方式。

### 8.6 动效节奏

| 动效类型 | 时长 | 缓动 |
| --- | --- | --- |
| 微交互 | 150ms-200ms | ease-out |
| 页面、抽屉、弹窗过渡 | 250ms-350ms | ease-in-out |
| 通知、徽章、强调反馈 | 400ms-600ms | spring |
| 通用缓动函数 | 按 token 输出 | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` |

动效只用于增强理解，不增加等待感，不阻断核心任务。

## 9. 内容策略设计

内容策略设计用于回答“界面上的文字用什么语气、什么词、什么动作引导”。

### 9.1 品牌语调

必须定义：

- 人格描述。
- 三条写作原则。
- 禁用词。
- 中英文混用规则。
- 专业术语使用边界。

### 9.2 关键页面文案

每个关键页面必须列出：

| 位置 | 要求 |
| --- | --- |
| 页面标题 | 说明当前页面任务，不使用空泛口号 |
| 副标题 | 补充页面价值或使用说明 |
| 主 CTA | 使用具体动词开头 |
| 辅助按钮 | 使用中性动作词 |
| 危险按钮 | 使用明确风险词并配合视觉警示 |
| 空状态 | 说明原因、给出下一步 |
| 错误状态 | 先安抚，再解释，再给恢复动作 |
| 加载中 | 说明系统正在做什么 |

### 9.3 状态文案框架

| 场景 | 文案规则 |
| --- | --- |
| 页面加载 | 告诉用户正在加载的对象 |
| 数据提交 | 告诉用户正在保存、发布或同步 |
| 文件上传 | 显示进度，不只显示 spinner |
| 列表为空 | 给出创建、导入或返回入口 |
| 搜索无结果 | 给出换关键词、清除筛选或扩大范围入口 |
| 权限错误 | 告知无权限和申请路径 |
| 404 | 告知页面不存在并提供返回入口 |

### 9.4 命名一致性

同一个实体必须在所有页面使用同一名称。禁止同时使用多个近义词指代同一业务对象。

必须输出术语表：

| 业务实体 | 界面统一名称 | 禁用别名 |
| --- | --- | --- |
| `<entity_id>` | `<display_name>` | `<forbidden_alias>` |

## 10. 设计知识库规则

设计知识库用于确定风格方向和行业参照，但不得替代 PRD。

### 10.1 内置设计知识优先

默认使用模型内置设计知识，不调用外部网站抓取视觉参考。

可使用的文字化参照包括：

| 用户偏好 | 可转化的风格特征 |
| --- | --- |
| 极简工具感 | 低饱和灰阶、克制主色、清晰层级、细边框、细腻阴影 |
| Linear / Vercel / Raycast 风格 | 高密度工作台、暗色或中性底、快捷搜索、轻量动效 |
| Notion 风格 | 内容优先、低装饰、可变宽度布局、黑白灰为主 |
| Glassmorphism | 背景模糊、半透明层、浅色边框、柔和光晕 |
| Brutalism | 强对比、大字号、硬边框、鲜明原色、低装饰 |
| Bento Grid | 不同尺寸卡片错落排布、统一圆角、统一内边距 |

### 10.2 用户参考材料

当用户提供本地截图、图片描述或文字风格说明时，必须提炼：

- 色彩。
- 字体。
- 间距。
- 圆角。
- 阴影。
- 背景质感。
- 边框。
- 图标。
- 插画。
- 图形风格。
- 信息密度。
- 动效性格。

当用户只提供 URL 时，不抓取 HTML，不读取视觉站点页面。必须提示主会话请求用户提供截图或本地参考文件。

### 10.3 禁止抓取规则

禁止直接抓取以下类型网站作为 UI 设计依据：

- 视觉作品集网站。
- 大量 JavaScript 渲染的灵感站。
- 需要登录的设计平台。
- 会产生大量脚本、样式和广告 token 的页面。

`ui-architect` 当前工具不包含 WebSearch 或 WebFetch，因此本流程不调用外部搜索和网页抓取。

- 3-5 个关键词。
- 情绪板文字描述。

- 明暗主题策略。

| 间距 | xl | 32px | 页面级间距、章节间距 |
| 间距 | xxl | 48px | 大区块间距、首屏上下留白 |
| 圆角 | sm | 4px | 小按钮、标签、输入框 |

### 11.5 背景质感与边框

背景质感必须定义：

- 主背景：纯色、微渐变或毛玻璃。
- 层级区分：灰度、透明度或背景块。
- 特殊质感：噪点纹理、网格底纹、渐变光晕或无特殊质感。

边框规则必须定义：

| 属性 | 规则 |
| --- | --- |
| 宽度 | `1px` 用于标准边框，`2px` 用于强调边框 |
| 颜色 | 亮色主题使用 `neutral.200`，暗色主题使用 `neutral.700` |
| 风格 | `solid` 用于常规边界，`dashed` 用于拖拽区域或待配置区域 |

### 11.6 图标系统

必须定义：

| 图标项 | 规则 |
| --- | --- |
| 图标库候选 | Lucide、Feather、Heroicons、Phosphor 或自定义 |
| 图标风格 | 线性、填充或双色 |
| 线宽 | 线性图标默认 1.5px 或 2px |
| 小尺寸 | 16px，用于内联文本和标签 |
| 中尺寸 | 20px，用于按钮和列表 |
| 大尺寸 | 24px，用于导航和标题 |
| 特大尺寸 | 32px 以上，用于空状态和功能图标 |

preview HTML 中不得引用远程图标库；必须使用内联 SVG 或 CSS 图形表达。

### 11.7 插画与图形风格

必须定义：

| 图形项 | 规则 |
| --- | --- |
| 插画类型 | 3D、等轴测、极简线框、手绘或无插画 |
| 插画角色 | 人物、抽象几何、品牌吉祥物或产品对象 |
| 使用场景 | 空状态、引导页、营销页、404、成功页 |
| 色彩限制 | 是否只使用品牌色和中性色 |
| 图形复杂度 | 与产品专业度和信息密度一致 |

preview HTML 中的插画只能使用内联 SVG 或 CSS 绘制，不引用远程图片。

## 12. preview HTML 设计

preview HTML 用于用户审核 UI 方向，不是生产代码。

### 12.1 文件规则

`preview.html` 必须满足：

- 单文件。
- 可直接用浏览器打开。
- 包含完整 `<!doctype html>`、`html`、`head`、`body`。
- CSS 写在同文件 `<style>` 中。
- JavaScript 只使用原生浏览器能力。
- 不引用远程图片、远程字体、CDN、外部脚本或外部样式。
- 不发起网络请求。
- 不包含真实鉴权、真实请求或真实业务数据提交。
- 底部显示“Prototype only, not production code”。

### 12.2 覆盖范围

preview HTML 必须覆盖：

- P0 用户任务涉及的页面。
- 核心导航。
- 至少一个关键表单或关键操作。
- 加载态。
- 空状态。
- 错误态。
- 成功态。
- 弹窗、抽屉、Tab 或页面切换中的关键交互。

### 12.3 示例数据

示例数据必须是脱敏假数据。禁止出现：

- 密钥。
- token。
- 真实手机号。
- 身份证号。
- 内部地址。
- 生产数据。
- 真实客户名称。

## 13. UI handoff 规则

`ui-handoff.md` 用于后续 `architect` 消费，不替代系统设计。

必须包含：

| 内容 | 规则 |
| --- | --- |
| 页面到数据需求 | 只描述页面需要展示、提交、变更的数据 |
| 页面到动作需求 | 只描述用户动作和系统反馈，不设计 API 实现 |
| 页面到模块候选 | 只给出 UI 视角候选模块，不生成正式 `module-split.json` |
| 前端目标文件候选 | 只列出候选路径和职责，不修改目标项目业务文件 |
| 验收关注点 | 映射 `AC-*` 并说明 UI 行为如何验证 |
| 风险 | 标记响应式、可访问性、状态复杂度、权限展示风险 |
| preview 结论 | 说明 preview 覆盖范围和用户审核关注点 |

## 14. UI 质量扫描

写入最终输出前必须完成以下扫描：

| 扫描项 | 通过标准 |
| --- | --- |
| 需求追溯 | 每个 P0 用户可见需求映射到页面、组件、交互或状态 |
| 新项目默认 | 未显式 brownfield 时，不读取、不引用、不依赖已有前端结构 |
| brownfield 边界 | 仅在 `project_mode=brownfield` 且 `existing_frontend=true` 时使用已有前端事实 |
| 页面完整性 | 每个核心页面有目标、入口、层级、动作和状态矩阵 |
| 信息架构 | 导航结构、信息层级、页面跳转、内容分类和搜索体验完整 |
| 交互闭环 | P0 任务流包含起点、成功路径、失败路径和恢复方式 |
| 内容一致性 | 同一业务实体在所有页面使用同一名称 |
| 视觉一致性 | 色彩、字体、间距、圆角、阴影、背景、边框、图标、插画、图形风格和动效统一 |
| 可访问性 | 焦点、键盘、ARIA、对比度和错误提示规则完整 |
| preview 自包含 | `preview.html` 不依赖外部网络资源 |
| 安全与隐私 | 无密钥、token、真实敏感数据、外部请求或远程资源引用 |
| 契约边界 | 未生成 PRD、系统设计、模块拆分、执行清单或目标项目业务代码 |

## 15. 输出顺序

固定输出顺序如下：

```text
ui-spec.md
page-map.md
interaction-flow.md
ui-handoff.md
preview.html
.superlooper/reports/<session_id>/upstream_alignment.md
design-tokens.json

```

`design-tokens.json` 和 `component-inventory.md` 是条件输出物。条件不满足时，不生成空文件。
