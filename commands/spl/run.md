# /superlooper:spl:run

`/superlooper:spl:run` 是运行分段触发入口，执行 `skills/superlooper/SKILL.md` 的流程五、流程六和流程七。此命令必须基于已校验通过的 `module-split.json`、已审核 UI 产物和已完成的项目结构初始化继续执行，生成 `execution_manifest.json` 后先输出 `execution_summary.md` 等待用户确认，不提供 `/spl:manifest`。

用户参数：`$ARGUMENTS`

执行规则：

1. 本文件中的 `python "${CLAUDE_PLUGIN_ROOT}/scripts/<script>.py" ...` 均表示插件根内脚本路径；安装态目标项目当前目录不要求存在 `scripts/`，目标项目根必须通过 `--workspace-root <workspace_root>` 传入。
2. 从插件安装根读取 `${CLAUDE_PLUGIN_ROOT}/skills/superlooper/SKILL.md`、`${CLAUDE_PLUGIN_ROOT}/schemas/execution-manifest.schema.json`、`${CLAUDE_PLUGIN_ROOT}/schemas/artifact-manifest.schema.json`、`${CLAUDE_PLUGIN_ROOT}/agents/developer.md`、`${CLAUDE_PLUGIN_ROOT}/agents/requirement-verifier.md`、`${CLAUDE_PLUGIN_ROOT}/agents/impact-analyzer.md`、`${CLAUDE_PLUGIN_ROOT}/configs/interaction-flow.json`；不得把这些插件文件解释为目标工作区相对路径。
3. 运行阶段对用户自然语言反馈必须先归一化为 `configs/interaction-flow.json` 中 `run` 阶段声明的 canonical action；`allowed_replies` 是内部 canonical reply 和推荐回复，不是用户唯一可输入内容。
4. 当用户在运行、测试、应用或需求反向校对阶段提出需求、UI 或设计变更时，必须归一化为 `change_impact_requested` / `需求变更，执行影响分析`；主调度器将反馈写入 `.superlooper/reports/<task_id>/change_feedback.md`，调用 `superlooper:impact-analyzer` 读取 PRD、UI 产物、系统设计、`module-split.json`、`execution_manifest.json` 和现有报告，生成 `.superlooper/reports/<task_id>/change_impact_report.md`，再调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/validate_miao_contracts.py" --workspace-root <workspace_root> --task-id <task_id> --scope change-impact-report` 校验报告。
5. 影响分析报告校验通过后，调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/update_session.py" --workspace-root <workspace_root> --task-id <task_id> --current-phase run --phase-status waiting_review --last-command "需求变更，执行影响分析" --active-feedback-report .superlooper/reports/<task_id>/change_feedback.md --change-impact-report .superlooper/reports/<task_id>/change_impact_report.md --report .superlooper/reports/<task_id>/change_impact_report.md --rollback-target-phase <rollback_target_phase> --invalidated-artifact <affected_artifact> --change-request-count <next_change_request_count> --next-action "审核 change_impact_report.md；通过后使用 影响分析通过，执行局部重跑；不通过使用 影响分析不通过，人工处理"`，其中 `--invalidated-artifact` 按报告数组重复传入，然后停止等待人工审核。此记录 checkpoint 不得传 `--affected-module` 或以其他方式写入非空 `affected_modules`；该字段在审核前必须保持空数组。
6. 用户确认 `影响分析通过，执行局部重跑` 后，必须先调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/resume_session.py" --workspace-root <workspace_root> --task-id <task_id> --user-input "影响分析通过，执行局部重跑"`，由脚本校验 `change_impact_report.md`，把批准范围持久化到 state 的 `affected_modules`，消费 `change_impact_report` 当前审核指针，并按 `rollback_target_phase` 推回合法阶段。局部重跑只调度 state 中列出的模块；`affected_modules` 为空且不处于局部重跑时才执行完整 Manifest DAG。用户选择 `影响分析不通过，人工处理` 时，必须停止自动执行并输出人工处理清单。
7. 运行阶段还必须识别 `代码审查未通过，返回修正`、`测试未通过，返回修正`、`应用冲突已处理，重新应用` 三个返工动作；这些动作只允许通过 `resume_session.py` 更新 state，不得直接写 state 或直接输出完成结论。
8. 确认 `.superlooper/context/<task_id>/ui/ui-handoff.md` 已进入系统设计上下文，且 `.superlooper/state/<task_id>.json` 中 `ui_status=APPROVED`、`ui_artifacts_validated=true`。
9. 确认 `.superlooper/manifests/<task_id>/module-split.json` 已通过 `module-split` 校验；`strict_review` 模式下还必须确认用户已审核模块拆分。
10. 确认 `.superlooper/state/<task_id>.json` 中 `project_initialized=true`，且 `initialization_report` 指向的报告存在。若不满足，停止并提示用户先完成初始化项目结构。
11. 在生成执行清单前，先调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/update_session.py" --workspace-root <workspace_root> --task-id <task_id> --current-phase run --phase-status running --last-command "/spl:run <task_id>" --generated-file .superlooper/manifests/<task_id>/module-split.json --next-action "等待执行清单和执行摘要生成完成"`。
12. 调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/generate_execution_manifest.py" --workspace-root <workspace_root> --task-id <task_id>`。
13. 调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/generate_runtime_agents.py" --workspace-root <workspace_root> --task-id <task_id> --agents-dir agents`；`--agents-dir agents` 相对插件根目录解析，运行时产物仍写入目标项目 `<workspace_root>`。生成当前 task 时不得清理其他 task 或当前 task 中未参与本轮生成的既有 runtime/registered 动态 Agent 文件。
14. 调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/validate_miao_contracts.py" --workspace-root <workspace_root> --task-id <task_id> --agents-dir agents --scope execution`；静态 `agents/`、`schemas/`、`configs/` 与 `commands/` 从插件根目录读取。
15. 调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/build_execution_summary.py" --workspace-root <workspace_root> --task-id <task_id>` 生成 `.superlooper/reports/<task_id>/execution_summary.md`，该脚本必须读取真实 `.superlooper/reports/<task_id>/upstream_alignment.md`。
16. 调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/validate_miao_contracts.py" --workspace-root <workspace_root> --task-id <task_id> --scope execution-summary` 校验执行摘要；校验失败或 `execution_summary_status=BLOCKED` 时不得启动并行开发。BLOCKED 摘要必须调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/update_session.py" --workspace-root <workspace_root> --task-id <task_id> --current-phase run --phase-status waiting_review --last-command "/spl:run <task_id>" --report .superlooper/reports/<task_id>/execution_summary.md --execution-summary-status BLOCKED --execution-summary-report .superlooper/reports/<task_id>/execution_summary.md --next-action "修正阻断项后回复 重试执行摘要"` 记录为 `run/waiting_review + BLOCKED`，唯一 canonical 恢复动作是“重试执行摘要”；不得以“按此执行”“执行”“开始并行开发”或普通“继续任务”恢复。用户明确重试时必须把原始输入交给 `resume_session.py`：前置校验失败继续保持 `run/waiting_review + BLOCKED`，全部通过后才回到 `run/pending + NOT_STARTED` 并重新生成摘要。`scripts/run_execution_dag.py` 如被使用，仅用于生成或校验 DAG state 和记录 script event，不是完整 executor，不得替代动态 `module_*` agent 调度、code review、merge、test、apply 和需求反向校对门禁。
17. 只有 `execution_summary_status=READY_FOR_APPROVAL` 时，才调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/update_session.py" --workspace-root <workspace_root> --task-id <task_id> --current-phase run --phase-status waiting_review --last-command "/spl:run <task_id>" --generated-file .superlooper/manifests/<task_id>/execution_manifest.json --generated-file .superlooper/agents/<task_id>/ --report .superlooper/reports/<task_id>/execution_summary.md --execution-summary-status READY_FOR_APPROVAL --execution-summary-report .superlooper/reports/<task_id>/execution_summary.md --next-action "审核 execution_summary.md；确认后回复 按此执行"`，然后要求用户回复“按此执行”或“执行摘要未通过，返回修正”。
18. 用户拒绝执行摘要后，必须把原始用户输入作为单个安全引用的 argv 调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/resume_session.py" --workspace-root <workspace_root> --task-id <task_id> --user-input <原始用户输入>`，由共享 reducer 归一化并写入 `.superlooper/reports/<task_id>/execution_summary_feedback.md`，同时保持 `rollback_target_phase=design`；不得在 adapter 中先替换为 canonical 文本。
19. 用户回复 `按此执行` 后，Claude adapter 必须先读取当前 task 的全部 registered Agent 文件 frontmatter，得到 `module_<module_id>__task_<sha256(task_id)[:16]>` 名称集合，并确认当前实际 Claude Code 会话的 Agent 工具可用类型列表包含全部名称。任一 registered scoped name 缺失时，不得调用 reducer，state 必须保持 `run/waiting_review + READY_FOR_APPROVAL`，唯一恢复提示为“启动新 Claude Code 会话，执行 `/superlooper:spl:resume <task_id>`，再次提交‘按此执行’。”。全部名称可用后，才调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/resume_session.py" --workspace-root <workspace_root> --task-id <task_id> --user-input "按此执行"`，由脚本重新校验 `execution_summary.md` 为 `READY_FOR_APPROVAL` 后推进到 `run/running`；不得直接调用 `update_session.py` 绕过执行摘要门禁。Manifest 和 runtime Agent 继续使用 logical name `module_<module_id>`，实际 Claude 动态 Agent 调用使用对应 registered scoped name。
20. `strict_review` 模式下可额外输出完整 Manifest 预览，并继续接受“执行”或“开始并行开发”，但这些等价批准动作也必须先通过第 19 条的 registered Agent 类型发现检查和执行摘要 reducer 门禁；默认 `standard` 模式不要求用户审核完整 Manifest。
21. 所有模块完成后，按 `skills/superlooper/SKILL.md` 校验模块产物。模块目录、`artifact_manifest.json` 和产物文件解析后的真实路径必须位于对应模块输出目录内，`produced_files[].path` 声明和实际产物文件均不得出现 Windows 等价重复路径。局部重跑时，所选模块全部完成且 artifact contract 校验通过后，必须调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/update_session.py" --workspace-root <workspace_root> --task-id <task_id> --current-phase run --phase-status running --last-command "/spl:run <task_id>" --clear-affected-modules --next-action "进入全局 code review、merge、test、apply 门禁"` 写入清理 checkpoint，再进入全局 code review。清空前中断恢复时继续按 state 中原 affected_modules 调度；清空后执行完整 DAG 的全局下游门禁，不得继续沿用旧局部范围。
21.1. 模块产物契约通过后调用 `superlooper:code-reviewer`；code review PASS 除零 blocker 外还必须包含非空、无重复且与当前 Manifest 完整模块集合完全一致的 `reviewed_modules`，否则不得调用 `superlooper:system_merger`。merge 必须在空 staging 重建完整快照，计算 `sha256:<64hex>` `snapshot_digest`，并事务式发布新快照与 `merge_report.json`；冲突、digest 或发布失败不得部分覆盖上一成功快照。只有 merge report 成功才调用 `superlooper:tester`，只有 test report PASS 才调用 `superlooper:workspace_applier`。apply 写入前必须重新计算 merged tree digest 并与 merge report 完全一致，把 create/overwrite 作为同一事务；apply I/O、工作区验证或成功报告发布失败都必须回滚，成功报告发布后才能清理 backup，`rollback.status=partial` 时必须保留 backup 并转人工恢复。这些 Claude 静态 Agent 的 scoped 调用名只属于 Claude 适配层，Manifest 中的 logical agent 名称保持不变。
22. 若 code review 失败，调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/update_session.py" --workspace-root <workspace_root> --task-id <task_id> --current-phase run --phase-status failed --last-command "/spl:run <task_id>" --report .superlooper/reports/<task_id>/code_review_report.md --last-error "代码审查失败，请检查 code_review_report.md" --next-action "代码审查未通过，返回修正"`；用户回复后必须由 `resume_session.py` 写入 `code_review_feedback.md` 并推回 `run/pending`。
23. 若 test 失败，调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/update_session.py" --workspace-root <workspace_root> --task-id <task_id> --current-phase run --phase-status failed --last-command "/spl:run <task_id>" --report .superlooper/reports/<task_id>/test_report.md --last-error "测试失败，请检查 test_report.md" --next-action "测试未通过，返回修正"`；用户回复后必须由 `resume_session.py` 写入 `test_feedback.md` 并推回 `run/pending`。
24. 若 apply 产生冲突或等待人工处理，调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/update_session.py" --workspace-root <workspace_root> --task-id <task_id> --current-phase run --phase-status blocked --last-command "/spl:run <task_id>" --report .superlooper/reports/<task_id>/apply_conflict_report.json --last-error "apply 阶段存在冲突或等待人工处理" --next-action "处理 apply 冲突后回复 应用冲突已处理，重新应用"`；用户回复后必须由 `resume_session.py` 校验冲突报告并推回 `run/pending` 重新应用。
24.1. 若 `apply_report.json.status=failed`，必须保持阻断。`rollback.status=success` 只允许在修复 I/O 原因后重新调用 `superlooper:workspace_applier`；`rollback.status=partial` 必须保留 `rollback.backup_dir` 并转人工恢复。两者都不得生成 session report 或最终完成结论。
25. 若 apply 成功，先调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/build_session_report.py" --workspace-root <workspace_root> --task-id <task_id>` 生成统一报告；再调用 `superlooper:requirement-verifier` 生成 `requirement_alignment_report.md`；然后调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/validate_miao_contracts.py" --workspace-root <workspace_root> --task-id <task_id> --scope requirement-alignment-report` 校验需求反向校对报告。
26. 需求反向校对报告校验通过后，调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/update_session.py" --workspace-root <workspace_root> --task-id <task_id> --current-phase requirement_alignment --phase-status waiting_review --last-command "/spl:run <task_id>" --report .superlooper/reports/<task_id>/apply_report.json --report .superlooper/reports/<task_id>/session_report.md --report .superlooper/reports/<task_id>/requirement_alignment_report.md --requirement-alignment-report .superlooper/reports/<task_id>/requirement_alignment_report.md --next-action "审核 requirement_alignment_report.md；回复 需求校对通过，完成交付 或 需求校对未通过，返回修正"`，并要求用户回复“需求校对通过，完成交付”或“需求校对未通过，返回修正”。
27. 用户回复 `需求校对通过，完成交付` 后，必须调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/resume_session.py" --workspace-root <workspace_root> --task-id <task_id> --user-input "需求校对通过，完成交付"`，由脚本重新校验 `requirement_alignment_report.md` 为 `PASS`、`unmet_requirement_count=0`、`unchecked_acceptance_count=0` 后推进到 `report/passed`；不得直接调用 `update_session.py` 绕过门禁。
28. 最后调用 `python "${CLAUDE_PLUGIN_ROOT}/scripts/build_session_report.py" --workspace-root <workspace_root> --task-id <task_id>` 重新生成包含需求反向校对结果的统一报告。

禁止事项：

- 不读取原始需求文档。
- 不提供 `/spl:manifest`。
- 不绕过 initialization_report、code review、merge report、test report、apply report、requirement_alignment_report 门禁。
